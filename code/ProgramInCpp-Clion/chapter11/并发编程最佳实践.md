## 核心概念

### 1. 线程基础 (`std::thread`)

**创建线程的方式：**
```cpp
// 1. 普通函数
thread t1(function_name);

// 2. Lambda
thread t2([]() { /* code */ });

// 3. 类成员函数
Worker w;
thread t3(&Worker::do_work, &w);

// 4. 带参数
thread t4(func, arg1, arg2);
```

**join vs detach：**
- `join()`: 等待线程完成（推荐）
- `detach()`: 线程独立运行（危险，慎用）

---

### 2. 互斥锁 (`std::mutex`)

**锁类型对比：**

| 特性 | lock_guard | unique_lock | scoped_lock |
|------|-----------|-------------|-------------|
| **RAII** | ✅ | ✅ | ✅ |
| **手动unlock** | ❌ | ✅ | ❌ |
| **条件变量** | ❌ | ✅ | ❌ |
| **多个mutex** | ❌ | ❌ | ✅ (C++17) |
| **性能** | 最快 | 略慢 | 快 |

**推荐使用顺序：**
1. `lock_guard` - 简单场景
2. `scoped_lock` - 多个mutex
3. `unique_lock` - 需要灵活性（条件变量）

---

### 3. 条件变量 (`std::condition_variable`)

**核心模式：**
```cpp
// 等待方
unique_lock<mutex> lock(mtx);
cv.wait(lock, []() { return condition; });  // 必须有谓词！

// 通知方
{
    lock_guard<mutex> lock(mtx);
    condition = true;
}
cv.notify_one();  // 或 notify_all()
```

**为什么需要谓词？**
- 防止**虚假唤醒**（spurious wakeup）
- 确保条件真正满足

---

### 4. 原子操作 (`std::atomic`)

**何时使用atomic：**
- ✅ 简单计数器
- ✅ 标志位（flag）
- ✅ 单个变量的读写
- ❌ 复杂的组合操作（仍需mutex）

**常用操作：**
```cpp
atomic<int> counter{0};

counter++;              // 原子递增
counter.fetch_add(1);   // 返回旧值
counter.load();         // 原子读取
counter.store(10);      // 原子写入
counter.exchange(20);   // 原子交换

// CAS操作（无锁编程核心）
int expected = 10;
counter.compare_exchange_strong(expected, 20);
```

### 5. Future和Promise

**适用场景：**
- 异步计算结果传递
- 线程间数据通信
- 异常传递

**选择指南：**

| 需求 | 使用 |
|------|------|
| 简单异步任务 | `std::async` |
| 手动控制 | `promise`/`future` |
| 可调用对象打包 | `packaged_task` |
| 多个线程等待 | `shared_future` |

## 最佳实践

### 实践1: 优先使用高层抽象

```cpp
// ❌ 避免
thread t(func);
t.join();

// ✅ 推荐
auto result = async(launch::async, func);
result.get();
```

### 实践2: RAII管理资源

```cpp
// ❌ 手动管理
mutex.lock();
// ... code ...
mutex.unlock();  // 异常不安全！

// ✅ RAII
lock_guard<mutex> lock(mutex);  // 异常安全
```

### 实践3: 最小化锁的范围

```cpp
// ❌ 锁粒度太大
lock_guard<mutex> lock(mtx);
expensive_computation();  // 不需要锁的操作
shared_data++;

// ✅ 缩小锁范围
expensive_computation();
{
    lock_guard<mutex> lock(mtx);
    shared_data++;
}
```

### 实践4: 避免死锁

```cpp
// ❌ 容易死锁
lock_guard<mutex> l1(m1);
lock_guard<mutex> l2(m2);

// ✅ 使用scoped_lock
scoped_lock lock(m1, m2);  // 原子性获取，避免死锁
```

### 实践5: 使用线程池

```cpp
// ❌ 频繁创建线程
for (auto& task : tasks) {
    thread t(task);
    t.join();
}

// ✅ 使用线程池
ThreadPool pool(4);
for (auto& task : tasks) {
    pool.enqueue(task);
}
```

## 性能优化

### 1. 减少锁竞争

```cpp
// ❌ 高竞争
mutex mtx;
for (int i = 0; i < 1000000; ++i) {
    lock_guard<mutex> lock(mtx);
    counter++;
}

// ✅ 使用atomic
atomic<int> counter{0};
for (int i = 0; i < 1000000; ++i) {
    counter++;  // 无锁
}
```

### 2. 读写锁分离

```cpp
shared_mutex rw_mutex;

// 多个读者可以同时持有
shared_lock<shared_mutex> read_lock(rw_mutex);

// 写者独占
unique_lock<shared_mutex> write_lock(rw_mutex);
```

### 3. 线程局部存储

```cpp
thread_local int counter = 0;  // 每个线程独立
```

### 4. 合理的线程数

```cpp
unsigned int cores = thread::hardware_concurrency();
ThreadPool pool(cores);  // 不要创建过多线程
```

## 常见陷阱

### ⚠️ 陷阱速查表

| 问题 | 症状 | 解决方案 |
|------|------|---------|
| **数据竞争** | 结果不确定 | 使用mutex或atomic |
| **死锁** | 程序挂起 | scoped_lock或固定顺序 |
| **忘记join** | 程序崩溃 | 析构前join或detach |
| **虚假唤醒** | 条件不满足被唤醒 | cv.wait使用谓词 |
| **异常不安全** | 资源泄漏 | RAII（lock_guard） |
| **锁粒度过大** | 性能差 | 缩小临界区 |
| **detach陷阱** | 悬空引用 | 避免引用局部变量 |

## 总结

### 并发编程核心原则

1. **安全第一** - 正确性 > 性能
2. **简单优于复杂** - 优先高层抽象
3. **RAII管理资源** - 异常安全
4. **最小化共享** - 减少锁竞争
5. **测试充分** - 并发bug难调试

### 记住

> **并发不是并行**
> - 并发（Concurrency）：处理多个任务的能力
> - 并行（Parallelism）：同时执行多个任务

> **过早优化是万恶之源**
> - 先保证正确性
> - 再优化性能
